# 使いやすく古びにくい文書

コマンドとログはスクリーンショットではなくテキストで示し、コードブロックにはプロンプト記号と説明文を入れない。
リンクの文字列にはリンク先の内容を書く。
「最新」「現在」のような時間に依存する語を避け、外部サイトへのリンクだけで説明を済ませない。
GUI の操作は、位置だけでなくボタンやメニューの名前で示す。

## 使いやすさ

- コマンド、ログ、エラーメッセージは、テキストで書き、スクリーンショットにしない。フォントやレイアウトのような見た目そのものを説明する場合に限り、画像を使う。
- リンクの文字列にはリンク先の題名か内容を書き、「こちら」「ここ」にリンクしない。
- コードブロックには、実行する内容だけを書く。
  - プロンプト記号（`$`、`#`、`>`）を付けない。
  - 操作の説明は、コードブロックの外に書く。
  - 入力と出力を分けたいときは、別々のコードブロックにし、出力のブロックの前に「出力」と書く。

コードブロックの書き方の例を示す。

````markdown
リポジトリをクローンする。

```shell
git clone https://example.com/repo.git
```

出力：

```text
Cloning into 'repo'...
```
````

## 古びにくさ

- 「最新」「現在」「近日」のような時間に依存する語を避け、バージョン、日付、条件を書く。例：「最新の JDK を入れる」ではなく「JDK 25 で動作を確認した」と書く。
- 外部サイトへのリンクだけで説明を済ませない。必要な内容を要約するか、必要な部分だけを引用し、出典として URL を添える。
- GUI の操作は、「右上」のような位置だけで示さない。ボタンやメニューの名前を併記する。
