# 箇条書きと表による構造化

列挙、手順、比較は、要素の関係に合わせて表、ラベル付きリスト、番号付きリスト、箇条書きのいずれかで示す。
同じ階層の要素は粒度と文末をそろえ、漏れと重複をなくす。
リストや表の前には導入文を置き、原因と結果をネストや文の細切れで表さない。

## 対象

この規約は、Issue、Pull Request、報告、規約、設計書の列挙、手順、比較に適用する。
論証を段落で進める記事、書籍原稿、ADR の Context は、[日本語技術文書の文章規範](japanese-tech-writing.md) のパラグラフライティングに従う。

## 形式の選び方

次の表の上の形式から順に、当てはまるかを検討する。
比較の軸や順序がない要素に、上位の形式を使わない。

| 形式             | 使う条件                                                                         |
| ---------------- | -------------------------------------------------------------------------------- |
| 表               | 複数の項目に共通の比較軸や属性がある                                             |
| ラベル付きリスト | 要素の抽象度や役割が異なり、単純に並べられない                                   |
| 番号付きリスト   | 手順、時系列、優先順位のように順序に意味がある。または番号で項目を指して議論する |
| 箇条書き         | 粒度のそろった要素を、順序なく並べる                                             |

- ラベル付きリストは「**ラベル**：説明」と書く。
- 読み手に選んでもらう選択肢には、「A 案」「B 案」のように記号を付ける。
- 状態遷移や複雑な条件分岐は、文章や例で説明せず、決定表か状態遷移図にする。

## 図の選び方

図で関係を示すときは、関係に合う形を選ぶ。

- **対比**：現状とあるべき姿のように、二つを並べて差を示す。
- **ツリー**：問題の分解や階層を示す。
- **ベン図**：範囲や責務の重なりを示す。
- **グラフ**：割合を円グラフで、数値の比較を棒グラフで、推移を折れ線グラフで示す。
- **ステップ**：分岐のない一直線の手順を示す。
- **サイクル**：終わりなく繰り返すプロセスを示す。要素は 3 から 6 程度にする。
- **フローチャート**：条件分岐を含む処理や判断を示す。流れは上から下か、左から右へそろえる。

三つ以上を比べるときは表を使い、比べた結論は記号や強調で示す。

## 項目の書き方

- 同じ階層の要素は、主語（利用者の視点かシステムの視点か）と文末（動詞か体言か）をそろえる。
- 同じ階層に抽象度の違う要素を並べない。細かい要素は、上位の要素の下へネストする。
- 漏れと重複をなくす。ただし、すべての観点の網羅は目的にせず、判断に効く軸を押さえる。
- リストや表の直前に、その内容が前提条件か手順かといった役割を示す導入文を置く。
- 項目だけを拾い読みしても意味が通じるように書き、「これ」「前述の」のような指示語に頼らない。
- 並列の要素を文の中に埋め込まず、箇条書きにする。項目は体言止めにしてよい。

悪い例：「修正範囲は、ログインボタンの色の変更と、ログアウトボタンの配置の調整です」。
良い例：「修正範囲は次のとおりである」の後に、「ログインボタンの配色変更」「ログアウトボタンの配置調整」を箇条書きにする。

## 避ける書き方

- 一続きの文章を細切れにして並べない。論理関係が消えるため、関連する文は一つの項目にまとめ、項目の役割をラベルで示す。
- ネストは包含関係の分類だけに使う。原因と結果は一文で書くか、「**原因**：」「**結果**：」のラベルを付けて同じ階層に並べる。
