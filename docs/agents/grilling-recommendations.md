# grilling の推奨に添える根拠

grilling の質問に推奨の答え（➡）を付けるときは、毎回、標準、避けるアンチパターン、規約と ADR との関係、自分の判断の4行を添える。
利用者が「標準に沿っているか」を聞き返さなくても、根拠を ➡ の下で確かめられるようにするためである。
推奨を標準、ベストプラクティス、アンチパターンで根拠づける規則は [設計判断の進め方](../principles/design-decision-process.md) が定める。
この文書は、その規則を grilling の出力に表す形だけを定める。

## 対象

`/grill-with-docs` と `/grilling` が、利用者への質問に推奨の答えを付けるときに適用する。
上流の [grilling の翻訳](matt-pocock-skills/grilling.md) は固定した上流版なので、この規則は上流の文書へ書かず、ここに置く。

## 形

推奨ごとに、次の4行を添える。

```markdown
➡ <推奨>

- 標準: <標準のやり方か。どの標準か> (<出典の URL。公式ドキュメント、そのツールのテンプレートやデフォルト>)
- 避けるアンチパターン: <この推奨が避けるもの>
- 規約と ADR: <沿うもの / 外れるもの。外れるなら、どの文書のどの推奨から、なぜ>
- 判断: <標準でなく自分の判断で決めた部分>
```

4行のどれも省かない。
該当がない行は、行を消さず、「なし」と理由を書く。

## 出典の確かめ方

- 出典は、そのラウンドを送る前に開いて確かめた URL だけを書く。
- 確かめていない記憶は「標準」の行に書かず、「判断」の行に、確かめていないと書く。
- 標準が見つからないときは、「標準: 見つからない (探した先)」と書く。探した先には、開いた公式ドキュメントや検索語を挙げる。

## 規約と ADR に外れる推奨

推奨が規約か ADR から外れるときは、「規約と ADR」の行に、外れる文書、その文書のどの推奨から外れるか、外れる理由を書く。
そのうえで、[docs文書の作成と変更](../knowledge/documentation-authoring.md) と [ADRの運用ルール](../adr/conventions.md) に照らして、ADR が要るかを確かめ、結果を同じ行に書く。

## ラウンドを送る前の点検

ラウンドを送る前に、そのラウンドのすべての ➡ に4行があることを確かめる。
4行がない ➡ は、足してから送る。

## この規則の上限

この規則は、エージェントが守ったかを、利用者が出力を読んで確かめる形にとどまる。
4行の有無と出典の URL は読んで分かるが、標準の判定が正しいか、URL の内容が主張を支えるかは、機械では検査していない。
検査を足す場合は、[学びを仕組みへ還元し続ける](../principles/continuous-reinforcement.md) の順に、検査できる層を探す。
