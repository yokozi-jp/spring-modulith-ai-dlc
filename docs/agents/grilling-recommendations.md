# grilling の推奨に添える根拠

grilling の質問に推奨の答え（➡）を付けるときは、毎回、「標準」「避けるアンチパターン」「規約と ADR」「判断」の4行を添える。
利用者が「標準に沿っているか」を聞き返さなくても、根拠を ➡ の下で確かめられるようにするためである。
推奨を標準、ベストプラクティス、アンチパターンで根拠づける規則は [設計判断の進め方](../principles/design-decision-process.md) が定める。
この文書は、その規則を grilling の出力に表す形を定める。
適用の範囲は、[設計判断の進め方](../principles/design-decision-process.md)の「対象」より広く、設計の質問に限らず、すべての ➡ に4行を添える。

## 対象

`/grill-with-docs` と `/grilling` が、利用者への質問に推奨の答えを付けるときに適用する。
`/triage`、`/wayfinder`、`/improve-codebase-architecture`、`/to-questionnaire` が `/grilling` を呼ぶときも同じである。
入口は [Matt Pocock スキル運用](matt-pocock-skills/workflow.md) と [RGDD の開発フロー](rgdd.md) のフェーズ2にある。
[上流の設計対話リファレンス](matt-pocock-skills/grilling.md)は固定した上流版の翻訳なので、この規則はそこへ書かず、ここに置く。

## 推奨に添える4行

推奨ごとに、次の4行を添える。

```markdown
➡ <推奨>

- 標準: <標準かベストプラクティスのやり方か。どの標準か> (<出典。公式ドキュメントの URL、そのツールのテンプレートやデフォルト>)
- 避けるアンチパターン: <この推奨が避けるもの>
- 規約と ADR: <沿うもの / 外れるもの。外れるなら、どの文書のどの推奨から、なぜ>
- 判断: <標準でなく自分の判断で決めた部分>
```

4行のどれも省かない。
「標準」以外の行に書くことがないときは、行を消さず、「なし」と理由を書く。
「標準」の行は、出典を書くか、次の節の「見つからない」と書く。
ラウンドを送る前に、そのラウンドのすべての ➡ に4行があることを確かめ、足りなければ足してから送る。

## 出典の確かめ方

- 出典は、そのラウンドを送る前に開いて確かめた URL か、実行して確かめたファイルとコマンドの出力だけを書く。
- 確かめていない記憶は「標準」の行に書かず、「判断」の行に、確かめていないと書く。
- 標準が見つからないときは、「標準: 見つからない（探した先）」と書く。探した先には、開いた公式ドキュメントや検索語を挙げる。

## 規約と ADR に外れる推奨

推奨が規約か ADR から外れるときは、「規約と ADR」の行に、外れる文書、その文書のどの推奨から外れるか、外れる理由を書く。
そのうえで、[ADR の運用ルール](../adr/conventions.md)の「ADR を作る基準」に照らして ADR が要るかを確かめ、結果を同じ行に書く。

## 守ったかの確かめ方

この規則は、エージェントが守ったかを、利用者が出力を読んで確かめる形にとどまる。
4行の有無も出典の有無も、機械では検査しない。
標準の判定が正しいかと、出典の内容が主張を支えるかは、出典を開かないと確かめられない。
検査を足す場合は、[学びを仕組みへ還元し続ける](../principles/continuous-reinforcement.md) の順に、検査できる層を探す。
