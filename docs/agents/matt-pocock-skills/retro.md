# エージェント環境の改善を提案する retro リファレンス

この文書は実行用の `SKILL.md` ではなく、固定した上流版の日本語リファレンスである。
プロジェクトでの運用は [Matt Pocock スキル運用](workflow.md) を優先する。

## 概要

`retro` は、コーディングセッションを振り返り、次の実行を良くするためのエージェントの環境の改善を提案する。
変更の対象はコードではなく環境である。
提案するだけで、利用者が候補を選ぶまで何も変更しない。

## 使う場面

利用者が `/retro` と入力して呼び出す。
`disable-model-invocation: true` を持つため、モデルは自動では起動しない。
上流は、探し物に時間がかかった、機械で検出できる誤りを出した、必要な情報に届かなかったといった、思うように進まなかったセッションの後を想定している。

コードの良否を判定したい場合は `code-review` を使う。

## 入力と前提

利用者が対象のセッションを指定する。
指定がなければ現在のセッションを対象にする。
別のセッションを指定された場合は、このマシンのセッションログを検索して一次資料を読む。

## 手順

1. `writing-for-agents` スキルを呼び出し、エージェント向け文書の書き方を読む。
2. 対象セッションの一次資料を読む。
3. 次の七つの観点で改善候補を探す。
4. 候補を深刻度の高い順に利用者へ提示する。

各候補は、セッションの具体的な出来事に遡れなければならない。

## 改善候補の観点

- **ナビゲーション**：正しいファイルを見つけるまでに時間がかかったときに、**ナビゲーションポインタ**を足す。隠れた依存があれば示す。
- **機械的検査**：エージェントの誤りを検出できた lint、型、テスト、ファイルシステムの検査を足す。
  先にリポジトリ自身の検査コマンドと CI を読み、すでにあるが接続されていない検査、または壊れている検査を指摘する。
  pre-commit hook も CI ジョブもないリポジトリは、それ自体を指摘する。
- **coding standards**：レビューエージェントに新しい規則を課すか、既存の規則を削除または明確化する。
  違反をまず分類する。
  機械的な違反（固定の構文パターン、禁止 API、import の形、ファイル配置）は、決定的な検査にする。
  判断を要する事項（ファイル横断の一貫性、周囲の書き方への一致）だけを `CODING_STANDARDS.md` に置く。
- **グローバル AGENTS.md**：肥大した `AGENTS.md` の内容のうち、coding standards または検査へ移すものを探す。
- **ツール経済**：高価なツール呼び出しや、トークン効率の悪い独自ツールを簡素化する。
- **no-op**：steering の指示のうち、エージェントの振る舞いを変えないものを削除する。
- **情報アクセス**：開発サーバーのログを残す、第三者サービスへの読み取り専用アクセスを与えるなど、必要な情報へ届く手段を増やす。

## 実装とレビューの責務

作業は実装とレビューの二段階を通る。
実装エージェントは探索、コード、デバッグを担い、コンテキストへの負荷が最も高い。
レビューエージェントは差分だけを受け取るため負荷が低い。
そのため、規約の強制は実装エージェントではなくレビューエージェントに担わせる。

## ファイルの置き場

- `CLAUDE.md` と `AGENTS.md` は、すべてのエージェントのコンテキストに入るため、ナビゲーションポインタに限って使う。
- `CODING_STANDARDS.md` は、実装時ではなくレビュー時に読まれる。1,000 行を超えたら docs へのポインタを足す。
- docs は他のファイルから指す参照資料にする。新規作成の前に既存の文書を探す。
- スキルは、description がコンテキストに入るため、文書の入口または利用者が呼び出すコマンドに使う。

## 成果物

深刻度順の改善候補の一覧を得る。
ファイル、検査、スキルの変更は、利用者が候補を選んだ後に行う。

## 関連スキル

`writing-for-agents` を、手順の最初に必ず呼び出す。
`code-review` は、`retro` が追加する coding standards の読み手である。
`ask-matt` は、実装後の最後の工程として `retro` を案内する。

## 注意点

実行時は対象セッションを消去する前に行う。
消去後は、そのセッションのログを指定して実行する。
候補を、セッションの出来事に結び付かない一般論で埋めてはならない。
機械的な違反を、`CODING_STANDARDS.md` の文章だけで済ませてはならない。
