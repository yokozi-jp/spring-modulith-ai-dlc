# To Questionnaire の質問票作成リファレンス

この文書は実行用の `SKILL.md` ではなく、固定した上流版の日本語リファレンスである。
プロジェクトでの運用は [Matt Pocock スキル運用](workflow.md) を優先する。

## 概要

`to-questionnaire` は、利用者だけでは答えられない事項を、別の一人が回答する Markdown の質問票へ変える。
質問票は非同期で記入して渡しても、一緒に会議で埋めてもよい。
受取人は利用者にない知識を持ち、質問票はその知識を引き出す。

## 使う場面

判断に必要な知識が利用者の中にもコードベースにもなく、別の人物が持っている場合に使う。
利用者が一人では解決できない判断または事実を、その人物から得る必要がある場面を対象とする。

## 入力または前提

送付先は一人である。
利用者は、受取人の役割、専門性、利用者との関係を答えられる必要がある。
利用者は、受取人から持ち帰る必要がある具体的な判断または事実を答えられる必要がある。

## 送付についてだけ質問する原則

利用者への interview は、利用者が必ず答えられる送付に関する事項だけを扱う。
対象分野そのものについて利用者を問い詰めてはならない。
利用者には誰へ送るか、何を受け取りたいかを尋ねる。
文書内の質問は、受取人が知っていることと利用者が必要とすることの差を対象にする。

## 手順

1. 誰へ送るかを一回の exchange で尋ねる。
受取人の役割、専門性、利用者との関係を確認する。
この情報によって質問票の語調と、質問票自体が持つべきコンテキスト量を決める。
受取人が誰であり、利用者にはない何を知っているかが分かれば、この手順は完了する。

2. 何を受け取る必要があるかを一回の exchange で尋ねる。
利用者だけでは解決できず、その人物から必要とする具体的な判断または事実を確認する。
利用者が最終的に何を実行または判断できる必要があるか、具体的な一覧を得れば、この手順は完了する。

3. 最初の二手順で判明した差を対象に質問票を書く。
後述の構成に従う。
現在のディレクトリへ `to-questionnaire-<slug>.md` という名前で保存する。
`slug` は話題から作る。
保存後にファイルの path を報告する。
ファイルが存在し、二手順目で利用者が挙げたすべての項目を質問が覆えば完了する。

## 質問票の構成

文書は discovery questionnaire として構成する。
利用者にはコンテキストがなく、受取人がそのコンテキストを持つという関係を保つ。
非同期では一回しか回答を得られない可能性があるため、質問を優先度の高い順に並べる。
質問が数個を超えたら、話題ごとの `##` 見出しでまとめる。

### 表題と送付情報

文書の先頭に質問票の表題を置く。
続けて、質問票の目的と、その回答にかかっている判断を書く。
差出人、受取人、回答をどこでどう使うかを書く。

```markdown
# <質問票の表題>

**Purpose:** <質問票が必要な理由と、その回答にかかっている判断>

**From:** <利用者>, **To:** <受取人>, **How your answers will be used:** <回答の利用先>
```

### 受取人向けのコンテキスト

`## Context` に、利用者の頭の中を知らない受取人が回答できるようにする一段落を書く。
よく答えるために十分な情報を含めるが、一ページ分の説明にはしない。

### 回答方法

`## How to answer` に期限とおおよその所要時間を書く。
部分的な回答と「分からない」という回答も役に立つと伝える。
不確かな事項は省略せず、不確かであることを示すよう求める。

### 話題ごとの質問

話題ごとに一つの `##` 節を作る。
各節の質問は優先度の高い順に並べる。
一つの質問では一つの事項だけを尋ね、複合質問にしてはならない。
各質問の直下に回答欄を置く。
誤読される可能性がある質問や、表面的な回答を招く質問に限り、なぜ必要かを一行で添える。

```markdown
### What load is the system expected to handle at launch?

_Why this matters: it decides whether we provision for burst traffic now or defer it._

>
```

### 最後の自由回答

`## Anything else?` で、尋ねていないが知るべきことがないかを最後に確認する。

## 成果物

成果物は、現在のディレクトリにある `to-questionnaire-<slug>.md` 形式の Markdown 文書である。
作成後にその path を利用者へ報告する。

## 関連スキル

原文には、関連スキルの名前は記載されていない。

## 注意点

対象分野について利用者を interview せず、送付先と必要な返答についてだけ尋ねる。
最初の二手順は、それぞれ一回の exchange で行う。
質問を複合させない。
利用者が必要としたすべての判断と事実を、質問票の質問で覆う。
