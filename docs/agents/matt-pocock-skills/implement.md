# 仕様またはチケットを実装する implement リファレンス

この文書は実行用の `SKILL.md` ではなく、固定した上流版の日本語リファレンスである。
プロジェクトでの運用は [Matt Pocock スキル運用](../../matt-pocock-skills.md) を優先する。

## 仕様に基づく実装の概要

`implement` は、利用者が仕様またはチケットで示した作業を実装する。
実装後の検査、コードレビュー、現在のブランチへのコミットまでを含む。

## 使う場面

実装対象が仕様または一連のチケットとして与えられているときに使う。

## 実装の入力と前提

利用者が示した仕様またはチケットを入力とする。
`/tdd` を使う場合は、テストを置くシームが事前に合意されている必要がある。
原文には、それ以外の前提の指定はない。

## 実装からコミットまでの手順

仕様またはチケットに記載された作業を実装する。

可能な場合は、事前に合意したシームで `/tdd` を使う。

実装中は型検査を定期的に実行する。
単一のテストファイルも定期的に実行する。
最後に全テストスイートを一度実行する。

作業が完了したら、`/code-review` で変更をレビューする。

レビュー後、作業を現在のブランチへコミットする。

## 完了条件と成果物

仕様またはチケットの実装、最後の全テストスイート、コードレビュー、現在のブランチへのコミットが完了すれば終了である。
成果物は、実装、検査結果、レビュー結果、現在のブランチ上のコミットである。

## 関連スキル

事前に合意したシームでテスト駆動開発を行える場合は、`tdd` を使う。
実装後のレビューには、`code-review` を使う。

## 実装するときの注意点

TDD は可能な場合に使うという位置付けであり、原文は常に必須とはしていない。
一方、型検査とテストの実行、完了後のコードレビュー、現在のブランチへのコミットは手順として要求されている。
原文には、明示された禁止事項はない。
