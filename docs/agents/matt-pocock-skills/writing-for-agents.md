# エージェント向け文書の書き方を示す writing-for-agents リファレンス

この文書は実行用の `SKILL.md` ではなく、固定した上流版の日本語リファレンスである。
プロジェクトでの運用は [Matt Pocock スキル運用](workflow.md) を優先する。

## 概要

`writing-for-agents` は、エージェントが読むあらゆる文書（スキル、`AGENTS.md`、`CLAUDE.md`、ポインタで届く docs）を書くための参照資料である。
形式は違っても書き方は同じで、エージェントは毎回同じ出力ではなく同じ過程をたどる。

## 使う場面

スキルの作成と編集、`AGENTS.md` と `CLAUDE.md` の変更に使う。
`retro` は、手順の最初にこのスキルを呼び出す。
書く文書がスキルのときは、同梱の `SKILL-MECHANICS.md` も読む。

## 書き方の原則

- **コンテキストポインタ**：コンテキストに置いた、文脈外の資料への参照である。
  スキルの description や、`AGENTS.md` の文書名を挙げた行が該当する。
  資料に届く条件と確実さは、宛先ではなくポインタの文言で決まる。
  先頭語を前に置き、分岐ごとに一つの引き金だけを書き、本文が持つ内容は切る。
- **二つの負荷**：常時読み込まれる資料はコンテキスト負荷を、人が覚える文書の存在は認知負荷を払う。
  ポインタ越しにだけ届く資料は、ポインタ一行の分だけ負荷を払う。
- **情報階層**：文書の内容を、手順、文書内の参照、別ファイルに分けた参照の順に置く。
  すべての分岐が必要とするものは文書内に置き、一部の分岐だけが必要とするものはポインタの先へ移す。
  同じ概念の定義、規則、注意点は一つの見出しの下にまとめる。
- **手順と完了条件**：各手順は、完了を判定できる条件で終える。
  曖昧な条件は早すぎる完了を招くため、確認でき、網羅的な条件にする。
- **分割**：手順の順序で分けるのは、後続の手順が現在の手順を急がせるときに限る。
- **先頭語**：モデルがすでに持つ簡潔な概念を、文ではなく語として繰り返す。
  禁止による誘導は禁止対象を想起させるため、望ましい振る舞いを肯定形で書く。
- **削る基準**：一つの意味を一か所にだけ書く。
  環境（スクリプト、設定、ディレクトリ構成）が持つ事実を文書に写さない。
  各行の関連性を確かめ、古くなった層を残さない。
  既定の振る舞いを変えない文は no-op として、文ごと削除する。

## スキル固有の呼び出し方式

`SKILL-MECHANICS.md` は、書く文書がスキルのときの追加の判断を定める。

- **モデル呼び出しのスキル**：description を持ち、エージェントが自律的に、または他のスキルが呼び出せる。
  description が常にコンテキストに載るため、常時のコンテキスト負荷を払う。
  `disable-model-invocation` を省略し、分岐を含むモデル向けの description を書く。
- **利用者呼び出しのスキル**：利用者が名前を入力したときだけ呼び出せ、他のスキルは呼び出せない。
  コンテキスト負荷はゼロだが、利用者がその存在を覚える認知負荷を払う。
  `disable-model-invocation: true` を設定し、description は利用者向けの一行にする。
- **ルータースキル**：利用者呼び出しのスキルが増えすぎたときに、他のスキルと使う場面を挙げる利用者呼び出しのスキルを一つ置く。
  案内するだけで、他のスキルを起動はできない。このリポジトリでは `ask-matt` が該当する。

## 成果物

このスキル自体は成果物を作らない。
呼び出したエージェントが、文書の書き方の基準として参照する。

## 関連スキル

`retro` が最初に呼び出す。
上流の `ask-matt` は、`AGENTS.md` や skill を書くときの参照先として案内する。

## 注意点

上流の `description` と文書は英語であり、このプロジェクトの日本語の文書にはそのまま適用しない。
日本語の技術文書の書き方、docs の作成手順、steering の作成手順は、プロジェクトの規約を優先する。
`docs/writing/index.md` と `docs/knowledge/documentation-authoring.md` と `docs/knowledge/steering-authoring.md` を読む。
