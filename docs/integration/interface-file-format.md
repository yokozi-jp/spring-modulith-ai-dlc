# 連携ファイルの形式と CSV の書き方

連携ファイルは RFC 4180 に従う CSV を原則とし、UTF-8 の BOM なし、CRLF、末尾の改行ありで出力する。
集信側は、BOM、LF、末尾の改行がないファイルも受け入れる。
固定長はレガシーシステムとの接続だけに使い、テキストの連携ファイルは圧縮しない。

## ファイル形式

- 原則として CSV を使う。
- データレイクなど分析用途への連携に限り、Parquet を使ってよい。
- 固定長は新しい設計で使わない。
  レガシーシステムとの接続に限り、新しいシステムの側が相手の形式に合わせる。
- テキスト形式の連携ファイルは圧縮しない。
  連携ファイルを長期に保管し、容量が大きい場合だけ、保管するときに圧縮する。

## CSV

- RFC 4180 を基準にする。
- ヘッダー行を必ず置き、項目の物理名を書く。
  日本語の論理名は書かない。
- コメント行を置かない。
- 区切り文字はカンマにする。
  タブにする場合は、システム内の連携ファイルを一律でタブにする。
- 囲み文字はダブルクォートにし、囲む必要がある項目だけを囲む。
  ライブラリの都合で難しい場合は、常に囲んでもよい。
- 項目内のダブルクォートは `""` と二つ重ねる。
- 項目内の改行はエスケープせず、項目を囲んでそのまま書く。
- 数値に正の符号 `+` と桁区切りのカンマを付けない（`1,000` ではなく `1000`）。
- 日付だけの値は `YYYY-MM-DD` で書く。
- 絶対時刻は `Z` 付きの RFC 3339 で書く（[日時とタイムゾーンの規約](../datetime/timezone-conventions.md)）。
- 空の項目は `,,` のように何も書かない。
- NULL は空文字と同じに扱う。
  区別が必要なファイルに限り、`#NULL` などプロジェクトで合意した値で表し、その扱いをするファイル種別を最小にする。

## 文字コード

- UTF-8 を使う。
  新しいファイル連携では必須とする。
- 配信側は BOM を付けない。
- 集信側は、先頭に BOM があれば読み飛ばして取り込む。
- レガシーな文字コード（Shift_JIS、EUC-JP、EBCDIC など）が必要な連携では、新しいシステムの側が変換を受け持つ。
- UTF-8 から Shift_JIS などへ変換する連携では、変換できない文字の扱いを連携仕様に書く。
  扱いは次のいずれかから選ぶ。
  - **中断**：処理を止め、元のデータを直してもらう。
  - **置換**：代替文字に置き換えて処理を続ける。
  - **削除**：変換できない文字を除いて処理を続ける。

## 改行コード

- 配信側は CRLF を使い、最終行の末尾にも改行を付ける。
- 集信側は LF も受け入れ、最終行の末尾に改行がなくても取り込む。

## 固定長で合意する事項

レガシーシステムと固定長で連携する場合は、次の事項を連携先と合意する。

- 長さを文字数で数えるかバイト数で数えるか。
  バイト数は出力する文字コードで数える。
- 使う文字コード。
- 文字列の詰め方向とパディング文字。
  マルチバイト文字を全角スペースで埋める場合は、1バイト余ったときの埋め方も決める。
- 数値の詰め方向と符号の位置。
  数値は右詰めのゼロ埋めにし、符号は先頭に置く（`00-10` ではなく `-0010`）。
- レコードの末尾に改行を入れるか。
