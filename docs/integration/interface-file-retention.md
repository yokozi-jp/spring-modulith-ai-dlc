# 連携ファイルの保持と削除

連携用のオブジェクトストレージはバージョン管理を有効にし、別のストレージへ複製するバックアップは原則として行わない。
保持期間を過ぎたファイルは、ライフサイクルポリシーで自動的に削除する。
組織内の連携ファイルは7日から30日程度、電子取引のファイルは法令の保存期間に従う。

## バックアップとストレージクラス

- オブジェクトストレージのバージョン管理を有効にする。
- 別のストレージへ複製するバックアップは行わない。
  DB のバックアップを別に取ることを前提とする。
- DR の要件がある場合だけ、別のリージョンへの複製を検討する。
- 古いファイルのストレージクラスは、アクセス頻度に応じて自動で階層を変える機能（S3 Intelligent-Tiering など）に任せ、手動の移行ルールを作らない。

## 保持期間

- 保持期間は、再実行できる期間の約束と監査の要件から決める。
- 保持期間を過ぎたファイルは、ライフサイクルポリシーで自動的に削除する。
- 組織内の連携で、配信元の DB から作り直せるファイルは、7日から30日程度にする。
  再取得の依頼（[誤った連携ファイルの訂正と再取得](interface-runbook-correction.md)）に備え、取り込み後の数日で消すほど短くしない。
- 機密情報を含むファイルは、[機密情報を含む連携ファイル](interface-file-security.md)に従い、できる限り短くする。
- EDI など電子取引に当たるファイルは、電子帳簿保存法などの法令が定める保存期間（原則7年）を確認して守る。
  取り込むときに加工したデータは元のファイルの保存の代わりにならないため、削除と変更を禁止した追記専用の領域にファイルを保存する。
