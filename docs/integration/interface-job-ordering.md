# ジョブとファイルの順序制御

連携ジョブは多重起動させず、前回が異常終了しても次回をそのまま起動できるように冪等に設計する。
集信はファイル名のタイムスタンプの古い順に処理し、異常なファイルを見つけたら取り込みを止める。
集信ジョブは、起動時に前回分の未処理ファイルを必ず確認する。

## ジョブの多重起動

- 前回のジョブが終わっていなければ、次のジョブを起動しない。
  この制御はワークフローエンジンの多重起動防止の機能で行い、アプリケーションに独自の排他を実装しない。
- 前回が異常終了しても、次回の定時起動でそのまま実行できるように設計する。
  手動の再実行を前提にしない。
- 前回の異常終了を解消するまで次回を実行させない連携では、ワークフローエンジンの制御に加え、アプリケーションでも前回の状態を確認する。

冪等な処理の作り方は[連携データの整合性と冪等性](interface-data-consistency.md)に従う。

## ファイルの処理順

- 集信側は、ファイル名のタイムスタンプ（またはシーケンス番号）の古い順に処理する。
  ファイル名は[連携用オブジェクトストレージのバケットとキー](interface-object-storage-layout.md)に従って付ける。
- 異常なファイル（スキーマ違反、データ不整合など）を見つけたら、取り込みを止めて連携先へ連絡する。
- 店舗やテナントのように独立した単位で構成されるデータで、一部の単位の不正を正常系としてスキップすると業務で決めている場合だけ、そのファイルをスキップして次へ進む。

## 前回分の未処理ファイル

- 配信側は、集信側が前回分を取り込んだかを確認しない。
- 集信ジョブは、起動時に前回分の未処理ファイルを必ず確認する。
- 全件連携で未処理ファイルがあれば、エラーで停止する。
  最新のファイルだけを取り込んでよいか、古いファイルから順に処理すべきかは、業務への影響を調べてから決める。
- 差分連携で未処理ファイルがあれば、古いファイルから順に処理する。
  順序を保証できない場合は、エラーで停止する。
- 業務上、古い差分ファイルの読み飛ばしが許される場合は、取り込みの状態をスキップとして記録し、スキップしたことをログに出す。
