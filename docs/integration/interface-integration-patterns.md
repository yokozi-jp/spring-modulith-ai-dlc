# システム間連携の方式選択

システム間のデータ連携は、ファイル連携を第一の選択肢にする。
DB 共有と、上流から下流へデータを送るプッシュ型の Web API 連携は採用しない。
メッセージングはデータ本体を運ばず、他の連携を起動する通知に使う。

## 対象

この規約は、別のシステムとの間でデータを受け渡す連携に適用する。
同じアプリケーション内のモジュール間の連携は対象外とし、[バックエンドアーキテクチャ](../backend/architecture.md)の公開契約とイベントに従う。
データ交換を目的としない SaaS の機能呼び出しも対象外とする。

## 用語

- **配信側**：連携データを作成して渡すシステム。
- **集信側**：連携データを受け取って取り込むシステム。
- **ファイル連携**：配信側が定めた形式のファイルを定めた場所へ置き、集信側がそれを取得する方式。
- **プッシュ型**：上流システムが起点となり、下流システムの Web API へデータを送る方式。
- **プル型**：下流システムが起点となり、上流システムの Web API からデータを取得する方式。

## 方式ごとの扱い

- **ファイル連携**：大量データの一括連携と、定時に起動する連携では原則としてこれを使う。
  新しく作る連携も、まずファイル連携で設計できるかを検討する。
- **DB 共有**：複数のシステムが同じ DB へ直接アクセスする方式は採用しない。
  DB リンク（`postgres_fdw` など）とマテリアライズドビューで他システムのテーブルを参照する方式も採用しない。
- **受信テーブル共有**：配信側が集信側の連携用テーブルへ直接書き込む方式は、原則採用しない。
  例外の条件は「受信テーブル共有の例外」節に従う。
- **プッシュ型の Web API 連携**：採用しない。
  代わりにファイル連携にし、データ鮮度の要件に合わせて出力の間隔を調整する。
  ファイル連携にできない場合も、少なくともキューを経由させ、集信側が取り込みの時期を制御できるようにする。
- **プル型の Web API 連携**：相手システムが Web API での連携しか認めない場合と、集信側が取得条件で対象を大きく絞り込める場合だけ認める。
  大量データや全件データを毎回取得する連携はファイル連携にする。
- **メッセージング連携**：「メッセージングの使い方」節に従い、通知に限って使う。

プル型の Web API を呼ぶ client は `infrastructure.client` に置き（[バックエンドの層の責務](../backend/layers.md)）、timeout、retry、circuit breaker は [ADR-019](../adr/ADR-019-define-resilience-and-capacity-guardrails.md) に従う。

## 受信テーブル共有の例外

次の条件をすべて満たす場合に限り、受信テーブル共有の採用を検討する。

- 連携基盤が、受信テーブルへの書き込みと集信側への通知を代行する機能を持つ。
- ファイルの生成と解析の負荷も削る必要があるほどデータ量が多く、秒単位のレイテンシ要件がある。
- 連携のスキーマがほとんど変わらない。

## メッセージングの使い方

- メッセージにはデータ本体を載せず、ファイルの配置などを知らせる通知だけを載せる。
- 通知には、イベント種別、送信元システム、ファイルの場所、件数、発生日時を含める。
- 発生日時は `Z` 付きの RFC 3339 で書く（[日時とタイムゾーンの規約](../datetime/timezone-conventions.md)）。
- データ鮮度の要件が数秒単位の場合に限り、データ本体をメッセージで連携してよい。
- ポーリングの間隔を短くする代わりに、上流が変更をメッセージで通知し、下流がその通知を起点にファイルまたはプル型の Web API で取得する構成を使ってよい。

通知メッセージの例を示す。

```json
{
  "eventType": "FILE_UPLOADED",
  "sourceSystem": "sales",
  "fileInfo": {
    "bucketName": "prd-sales-outbound-crm",
    "objectKey": "m_customer/dt=2026-10-01/m_customer_delta_20261001T063012123Z_0192a4b2-7c1e-7d3a-9f00-2b1c3d4e5f60.csv",
    "recordCount": 1500
  },
  "eventTime": "2026-10-01T06:30:13Z"
}
```

## 分析基盤への連携

- データソースが DWH のレプリケーション機能の対応範囲（RDB や KVS）にある場合は、DWH への自動レプリケーションを使う。
- それ以外で、DWH が外部のデータを直接読める形式なら、DWH からデータソースへ直接クエリを発行する連携を使う。
- どちらも使えない場合は、オブジェクトストレージを経由したファイル連携にする。
