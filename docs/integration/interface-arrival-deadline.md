# 連携ファイルの門限チェック

決めた時刻に連携する仕様では、集信側が門限チェックを必ず行う。
門限には遅延の許容幅を設け、その間はポーリングで確認し直してから通知する。

## 用語

- **門限チェック**：決めた時刻までに連携ファイルが到着しているかを集信側で確認する処理。

## 集信側の門限チェック

- 決めた時刻に連携する仕様では、集信側が門限チェックを必ず行い、配信側のチェックに頼らない。
- 門限チェックは、0件でも空ファイルが配信されることを前提にする（[連携ファイルのレイアウト](interface-file-layout.md)）。
- 門限に遅延の許容幅を設け、その間は一定の間隔で確認し直す。
  例：20時に連携するファイルなら、20時から5分間、1分ごとに確認する。
- 許容幅を過ぎても未着なら、エラーログを出して通知する。
  ログの書き方は[可観測性データの規約](../observability/conventions.md)に従う。

## 配信側の遅延監視

- 配信側は、ワークフローの中で影響が大きく遅れやすい重いジョブの遅延を必ず監視する。
- 配信ファイルを作るジョブそのものの遅延監視は任意とする。
  相手の業務への影響が大きい場合は、遅延をできるだけ早く検知できる時点で確認する。

## 運用ルール

- 未着を検知したときの問い合わせ先、エスカレーションの流れ、手動で再送する手順を、連携先と事前に決める。
