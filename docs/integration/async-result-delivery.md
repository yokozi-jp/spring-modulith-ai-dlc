# 非同期処理の結果の通知と待ち合わせ

完了の通知は、クライアントのポーリングか、利用者が一覧で確かめるオンデマンド確認を第一に検討する。
プッシュ通知は即時性の要件を満たせない場合に限り、一方向の通知なら Server-Sent Events を使う。
バックエンド内で完了を待つ同期待ち合わせは避け、必要な場合はステータス管理テーブルのポーリングとタイムアウトで実装する。

用語は[メッセージングの設計](async-messaging-design.md)の定義に従う。

## 通知の方式

通知の方式は、利用者が完了をどの程度すぐに知る必要があるかと、利用者が完了を画面で待っているかで選ぶ。

- **ポーリング**：画面がステータスを定期的に問い合わせる。利用者が画面を開いて待つ場合に向き、ポーリング間隔の分だけ遅れる。
- **プッシュ通知**：処理の完了時にサーバーからクライアントへ通知する。画面を開いていなくても届くが、通知基盤の構築と運用の費用が高い。
- **オンデマンド確認**：利用者がジョブ一覧や通知一覧を自分の都合で開いて確かめる。ステータス一覧の API だけで実装できる。

ポーリングかオンデマンド確認を第一に検討する。
プッシュ通知は利用者の作業を中断させるため、チャットのように即時性が業務に必要な場合に限る。

- **ポーリング**：処理時間が数分程度の場合に使う。画面では server state として TanStack Query で再取得し（[フロントエンドのルーティングと状態管理](../frontend/routing-and-state.md)）、間隔を指数的に延ばして無駄な要求を減らす。
- **プッシュ通知**：ポーリングで即時性の要件を満たせない場合に検討する。アプリケーションの通知の前に、メールやチャットツールなど既存の仕組みを使えないかを確かめる。アプリケーションで通知する場合も、届かなかった場合に備えてオンデマンド確認を併用することが多い。
- **オンデマンド確認**：ステータス管理テーブルを参照して一覧を返す（[非同期処理のステータス管理](async-job-status.md)）。

## サーバープッシュの方式

プッシュ通知をブラウザへ届ける方式は、次の三つから選ぶ。

- **ロングポーリング**：サーバーが更新まで応答を保留し、応答後にクライアントが再接続する。再接続を自前で実装する古い手法である。
- **Server-Sent Events**：HTTP の一つの接続を保ち、サーバーからクライアントへ一方向にデータを送り続ける。ブラウザが自動で再接続する。
- **WebSocket**：サーバーとクライアントが双方向にメッセージを送受信する。接続を保つステートフルな通信のため、ロードバランサーやデプロイ時の切断への考慮が必要になる。

非同期処理の完了通知のような一方向の通知には、Server-Sent Events を使う。
HTTP に基づくため、既存のロードバランサーやプロキシと併用しやすい。
WebSocket は、双方向のリアルタイム通信が必要な場合に限って検討する。

## 同期待ち合わせ

**同期待ち合わせ**：処理は非同期にしたまま、呼び出し元が完了まで待って結果を同期的に受け取ること。
負荷の平準化のために専用の実行環境へ切り出した重い計算を、利用者へ即時に返したい場合などに必要になる。

まず、同期待ち合わせをなくせないかを検討する。
クライアントのポーリングへ置き換えるのが最も単純であり、即時性を多少犠牲にしても、よほどの業務上の効果がない限り同期待ち合わせを作らない。

同期待ち合わせが必要な場合は、次の二つから選ぶ。

- **DB ポーリング**：プロデューサーが、ステータス管理テーブルのジョブが SUCCEEDED または FAILED になるまで DB を問い合わせる。状態は DB に永続化されるため、プロデューサーが落ちても問い合わせをやり直せる。
- **リプライキュー**：プロデューサーが要求メッセージに応答先のキューと相関 ID を付け、応答先のキューを監視して応答を待つ。応答専用のキューと相関 ID の紐づけが必要になる。

ステータス管理テーブルがある前提で、DB ポーリングを第一の選択肢にする。
問い合わせの間隔のあいだは DB 接続を返却し、待機中に接続を占有しない（[ADR-019](../adr/ADR-019-define-resilience-and-capacity-guardrails.md)）。

どちらの方式でも、待ち合わせのタイムアウトを設計する。

- タイムアウトしたらバックエンド内の待ち合わせをやめ、クライアントへ応答を返す。
- タイムアウトの後に処理が完了した場合の扱いを決める。
