# 誤った連携ファイルの訂正と再取得

ファイルは集信側が取りに行く構成なので、再取得の依頼には集信側の再取得で応じる。
配信側のデータの誤りは、DB を直してからファイルを作り直す。
誤送信は、集信側が取り込む前なら削除して作り直し、取り込んだ後は補正データの再連携を優先する。

## 再取得を求められたとき

1. 対象のファイルが保持期間内に残っていることを確認する。
   保持期間は[連携ファイルの保持と削除](interface-file-retention.md)に従う。
2. 集信側に、対象のファイルの取り込み完了のタグを未処理に戻して取得し直してもらう。
3. 配信側から書き込む構成で再送する場合は、元のファイルと区別できる別の名前で置く。
   [連携用オブジェクトストレージのバケットとキー](interface-object-storage-layout.md)の命名に従えば別の名前になる。

## 配信側のデータに誤りがあったとき

1. 配信側の DB をデータパッチで直す。
2. 直した DB からファイルを作り直す。
3. 集信側へ再取り込みを依頼する。

急ぐ場合は、ファイルを手で直して再取り込みを依頼してよい。
その場合も DB を必ず直し、DB とファイルの差異を残さない。

## 集信側が取り込む前に誤送信に気付いたとき

1. 集信側に、誤ったファイルの取り込みを止めてもらう。
2. 誤ったファイルを削除する。
3. 正しいデータでファイルを作り直す。
4. 集信側へ再取り込みを依頼する。

## 集信側が取り込んだ後に誤送信に気付いたとき

次のどちらかを集信側と相談して選ぶ。
補正データを作れる場合は、補正データの再連携を優先する。

- **補正データの再連携**：誤ったデータを取り消す補正データのファイルを作り、集信側に取り込んでもらう。
- **双方のデータパッチ**：ファイルを再連携せず、双方のシステムで誤ったデータをデータパッチで消す。
  集信側の後続処理への影響を調べてから行う。

補正データを連携できるレイアウトは[連携ファイルのレイアウト](interface-file-layout.md)の「取り消しの表し方」に従う。
