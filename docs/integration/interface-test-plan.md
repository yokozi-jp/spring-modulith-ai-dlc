# I/F テストの計画

I/F のテストは、プロジェクトのテスト計画の一部として、テストの工程と機能の区分に漏れと重複がないように計画する。
連携先の担当が異なる場合は、テストの範囲、責任分界点、スケジュール、体制、連絡先を連携先と合意する。

## 計画に含める項目

1. **方針**：目的と位置付け、テストの対象、前提と制約（使える環境、実施の順序、人員と期間）、I/F の経路上のすべてのシステムを載せた環境の構成図、参照する設計資料。
2. **テストの範囲**：対象のシステムと経路の向き、範囲の境界にする DB やストレージやキュー、システムごとの責任分界点、テスト観点。
3. **準備**：テストシナリオ、テストパターン表、テスト項目の粒度、テストデータの対象と量と作成方法と作成担当。
4. **実施**：障害の扱い、実施の方法とツール、クライアント環境、接続先、アカウントの管理。
5. **管理**：チケットの状態と流れ、エスカレーションの流れ、完了とみなす状態と進捗を確認する時点、成果物、体制と連絡方法、マイルストーン単位のスケジュール。

各項目の順序は、関係者の関心に合わせて入れ替えてよい。

## 準備と実施の規則

- テストデータに機密情報を含める場合は、マスキングや暗号化の方法を決める（[機密情報を含む連携ファイル](interface-file-security.md)）。
- テストの実施中に見つかった障害はその場で直さず、対応期間を決めて改修する。

## テスト観点

次の観点を必須とする。

- **正常系**：入力データ、出力データ、データの状態と区分値の組み合わせ、連携先からの応答の各パターンを網羅する。
- **冪等性**：運用テストで、同じ連携を再実行しても結果が変わらないことを確かめる。
- **大容量データ**：大きなデータで連携できることを確かめる。
  性能試験で確かめる場合は除く。
- **性能**：応答時間とスループットを確かめる。
  性能試験で確かめる場合は除く。

次の観点は、要件に応じて加える。

- リクエストと応答のエラー
- 連携先の障害を想定した可用性のテスト
- 非機能要件に基づくセキュリティの確認
