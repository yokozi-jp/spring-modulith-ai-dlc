# 非同期メッセージのセキュリティ

メッセージングの基盤を外部へ公開せず、送受信の権限を必要な処理だけに与える。
メッセージには個人情報と秘密情報を載せず、参照用の内部 ID だけを渡す。
コンシューマーは受け取ったメッセージを検証してから処理する。

用語は[メッセージングの設計](async-messaging-design.md)の定義に従う。

## 基盤へのアクセス

- メッセージの登録は Web API のサーバーなどアプリケーションを経由させ、メッセージングの基盤を直接外部へ公開しない。
- 最小権限の原則に従い、キューへの送信と受信の権限を必要な処理だけに与える。
- 基盤への通信はプライベートネットワークの経路に限り、インターネットへ公開しない。
- 基盤のサーバー側暗号化を有効にする。
- 外部ブローカーの資格情報は秘密情報として管理し、設定ファイルに書かず外部から注入する（[ADR-008](../adr/ADR-008-single-application-yaml-external-config.md)）。

## メッセージに載せる値

メッセージのペイロードには、個人情報と秘密情報を入れない。
コンシューマーには内部 ID だけを渡し、内容は DB から参照させる。

Spring Modulith はイベントを直列化してイベント出版レジストリに保存し、`completion-mode: archive` では完了したイベント出版も調査用の履歴として保持する。
そのため、[可観測性データの規約](../observability/conventions.md)でログへ出さないと定めた値は、イベントにも載せない。

ペイロードが ID だけでも、PCI DSS などのコンプライアンス要件がクライアント側の暗号化を求める場合は個別に対応する。
該当する要件がなければ、クライアント側の暗号化は行わない。

## コンシューマーでの検証

コンシューマーは、不正なメッセージを処理しないよう、受け取ったメッセージを検証する。
スキーマの検証に加え、業務上の意味として処理してよいデータかを確かめる。
