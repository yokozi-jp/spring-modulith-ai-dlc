# 新規帳票を作るかの判断基準

帳票の新規作成は、作らない、システム間連携、画面、帳票の順に検討し、前の手段で満たせない場合だけ帳票にする。
法令上の様式、取引先との合意、現物との紐付け、端末を使えない現場のいずれかに当たる場合は、帳票にすることを検討する。
帳票にする場合も、紙より電子帳票を先に検討する。

## 検討の順序

帳票は一度定着すると業務と結び付き、変更や廃止が難しくなる。
そのため、次の順に検討し、最初に要件を満たした手段を選ぶ。

1. **作らない**：念のために用意する程度の帳票は作らない。
2. **システム間連携**：EDI や API で相手のシステムへ直接渡せるなら、帳票にしない。方式は[システム間連携の方式選択](../integration/interface-integration-patterns.md)に従う。
3. **画面**：即時の確認や分析が目的なら、検索やドリルダウンができる管理画面や BI で提供する。
4. **帳票**：上のいずれでも要件を満たせない場合だけ、帳票として設計する。

## 帳票にする条件

次の条件に当たる場合は、帳票にすることを検討する。
出力形態は、各条件の判断の列に従って決める。

| 条件                                                                       | 例                                                         | 出力形態の判断                                                                          |
| -------------------------------------------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 法令やコンプライアンス上、特定の様式での保存または交付が義務付けられている | インボイス、領収書、財務諸表                               | 電子での保存を第一に検討し、電子保存の要件を満たせない場合だけ紙にする                  |
| 取引先との取引内容を確定させ、合意の証跡にする                             | 注文書、契約書、納品受領証                                 | 取引先が電子化を受け入れるなら電子帳票、受け入れないなら紙にする                        |
| モノと情報の移動を同期させる                                               | 配送伝票、現品票、ピッキングリスト、入館証                 | QR コードとスマートフォンの画面などで代替できるなら画面、荷物への貼付が必要なら紙にする |
| 端末を使えない現場で使う                                                   | 油で汚れる工場、防爆エリア、手袋でタッチ操作ができない現場 | 紙にする                                                                                |

どの条件にも当たらず、システム間連携と画面でも要件を満たせない場合は、要件を見直す。
電子帳票の形式は[電子帳票の形式選択](electronic-format.md)に、紙帳票の印刷は[紙帳票の印刷方式と用紙](paper-printing.md)に従う。

## 障害時の業務継続のための出力

基幹システムが止まっても最低限の業務を続けるために、どのデータが必要かを洗い出す。
必要なデータは、CSV や Excel のような汎用形式で出力する機能を、事業継続のための機能として組み込むかを検討する。
たとえば受注システムが止まったときに電話で受注を続けるには、直近の注文一覧と在庫表が要る。
