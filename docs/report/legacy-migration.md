# 既存帳票の棚卸しと移行方針

システムを置き換えるときは、既存帳票の全量を棚卸しし、利用実績に基づいて帳票ごとに移行方針を決める。
移行方針は、廃止、画面化、BI 化、システム間連携、電子帳票、現状維持の6つから選ぶ。
取引先へ出す帳票は、取引先と調整したうえで段階的に移行する。

## 棚卸し

- 設計書、ソースコード、ワークフローの定義、実行ログから帳票一覧を作り、全量を把握する。
- 現行どおりを正とせず、出力、参照、印刷、ダウンロードの実績で判断する。
- 「使うかもしれない」という意見だけを、帳票を残す根拠にしない。
- 出力されていても誰も参照、印刷、ダウンロードしていない帳票は廃止する。

## 移行方針の判定

帳票ごとに次の順で判定し、最初に当てはまった方針を選ぶ。

1. 過去1年以内の利用実績がなければ、**廃止**にする。
2. 法令上の義務または取引先の指定があり、現品票、貼付、現場の制約などで物理的な媒体が必須なら、**現状維持**にする。
3. 法令上の義務または取引先の指定があり、物理的な媒体が必須でなければ、**電子帳票**にする。
4. 後続システムへ再入力する原資として使われていれば、**システム間連携**にする。
5. 集計や推移の確認が目的なら、**BI 化**にする。
6. 検索や状態の確認が目的で、画面で代替できれば、**画面化**にする。
7. 持ち出しや証跡が必要で、画面で代替できなければ、**電子帳票**にする。

電子帳票の形式は[電子帳票の形式選択](electronic-format.md)に従う。
システム間連携の方式は[システム間連携の方式選択](../integration/interface-integration-patterns.md)に従う。

## 移行の方針

- 稟議、月次報告、在庫確認のように社内で完結する帳票は、ワークフローやダッシュボードへの移行を原則とする。
- システム外で運用されている表計算のマクロやデスクトップデータベースなどの利用者が作った仕組みは、原則として移行の対象にしない。
- 利用者が作った仕組みについては、CSV や Excel によるデータの提供までをシステムの責任とし、その先を利用者の責任とする線引きを移行の最初に合意する。
- 取引先へ出す紙帳票は、当面は現行の形式を受け入れ、業界標準のデータ交換基盤などへの電子化を中長期で進める。
- 新旧の並行稼働を含む移行計画は、取引先と調整して決める。
- 取引先の都合で現状維持になる帳票が残ることを前提に、移行計画を立てる。
