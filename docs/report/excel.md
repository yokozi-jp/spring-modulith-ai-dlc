# Excel 帳票の設計

Excel 帳票はテンプレートのファイルへ値を流し込んで生成し、1列1項目のリスト形式で出力する。
マクロを使わず、合計などの計算はサーバーで計算した値を出力する。
厳密な改ページやページごとの合計が必要な帳票は、Excel にせず PDF にする。

## 生成方式

- レイアウトは xlsx のテンプレートで定義し、プログラムは値を流し込むだけにする。
- テンプレートは、レイアウトの微調整をビルドなしのファイルの差し替えで済ませられるように管理する。
- テンプレートに、別のブックを参照する数式（`[Book1.xlsx]` のような記述を含む数式）を残さない。
- テンプレートを作るときは、値の貼り付けなどで外部参照を切る。
- リリース前に、外部参照先へアクセスできない環境でテンプレートを開き、エラーが出ないことを確認する。

## 改ページ

- 改ページの位置と1ページの行数はプログラムで制御せず、印刷の設定は利用者に委ねてデータを連続して出力する。
- 1ページに収まる行数はプリンタドライバや OS の解像度の設定で変わるため、プログラムで制御しても利用者の環境でずれる。
- ページごとの合計や厳密な改ページが必須の帳票は、[PDF 帳票の設計](pdf.md)に従って PDF にする。

## シートの形式

- 1列1項目のリスト形式で出力する。
- 全列を細くしてセルを結合する方眼紙形式にしない。並べ替え、絞り込み、別のシステムへの再取り込みができなくなり、スクリーンリーダーでも読み上げにくいためである。
- 見た目を重視する帳票は PDF、データを重視する帳票は Excel のリスト形式と使い分ける。

## マクロ

- マクロ付きの Excel（`.xlsm`）を配布しない。インターネットから取得したファイルのマクロは OS や Office のセキュリティ機能でブロックされるためである。
- ロジックはサーバーで処理し、結果の値を出力する。
- 動的な挙動が必要な場合は、Excel ではなく Web アプリケーションの機能として作る。

## 計算式

- 合計や税額などは、サーバーで計算した値を出力する。端数処理が Excel とサーバーで異なると、システム上の金額と一致しなくなるためである。
- テンプレートに業務ロジック（端数の切り捨てなど）を持たせない。
- ページごとの合計のように、改ページと同期してサーバーで計算しにくい単純な集計に限り、`=SUM(A1:A20)` のような数式を使ってよい。
- 数式を使う場合は、四則演算と単純な集計関数に限る。

## 保護

| 用途                                               | 保護の方法                 |
| -------------------------------------------------- | -------------------------- |
| 共有フォルダに置くファイルの誤った上書きを防ぐ     | 読み取り専用を推奨する設定 |
| 請求書などのレイアウトや数式を壊されないようにする | シートの保護               |
| 機密情報を送付する                                 | 読み取りパスワード         |

- 機密情報は、読み取りパスワードを付けたファイルを送る前に、Web からのダウンロードで渡せないかを検討する。
- シートを保護すると絞り込みなどの操作も制限されるため、利用者が使う操作を確認してから保護する。
- 書き込みパスワードは設定しない。

## 文字コード

内部処理から出力まで UTF-8 で統一する。
xlsx の内部の XML は UTF-8 であるため、変換が要らない。

## 大量出力

- 明細の行数が不定、または数千行を超える可能性がある帳票は、ブック全体をメモリへ展開せず、ストリーミング型の API（Apache POI の SXSSF など）で書き出す。
- 大量出力になる帳票は、ヘッダーと単純な明細のリストのように、ストリーミングで書き出せるレイアウトを設計の段階で選ぶ。
- セルスタイルはループの中で生成せず、事前に作ったものを使い回す。xlsx のセルスタイルの数には約6.4万の上限がある。
