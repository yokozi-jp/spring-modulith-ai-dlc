# PDF 帳票の設計

フォントは埋め込まないことを第一に検討し、外字がある場合と閲覧環境を予測できない場合だけサブセット埋め込みか画像化にする。
法的な証拠が要る帳票の電子署名は電子契約サービスへ委譲し、自前で実装しない。
社内向けの帳票にはパスワードを設定せず、保管先とシステムのアクセス権限で保護する。

## フォントの埋め込み

| 方式               | 内容                         | 再現性                       | ファイルサイズの増加の目安     | テキスト検索 |
| ------------------ | ---------------------------- | ---------------------------- | ------------------------------ | ------------ |
| 全埋め込み         | フォントファイル全体を含める | 確実                         | 日本語フォントで 3MB から 10MB | できる       |
| サブセット埋め込み | 使う文字のグリフだけを含める | 確実                         | 数百 KB                        | できる       |
| 埋め込みなし       | 閲覧端末のフォントを使う     | 環境に依存し崩れることがある | なし                           | できる       |
| 画像化             | 文字を画像や図形として描く   | 確実                         | 解像度と文字量による           | できない     |

- 埋め込みなしを第一に検討する。大量出力、長期保存、ネットワーク帯域への影響がファイルサイズに比例して大きくなるためである。
- 埋め込みなしで足りるのは、OS 標準のフォントだけを使う場合と、閲覧端末とプリンタのフォントが統制されている場合である。
- 外字や特殊文字がある場合は、サブセット埋め込みか画像化にする。
- 帳票ミドルウェアが外字をビットマップやベクター画像として埋め込む機能を持つ場合は、その機能で画像化してよい。
- 一般消費者向けのように閲覧環境を予測できない帳票は、サブセット埋め込みにする。
- 全埋め込みは選ばない。

## 画像

ロゴや印影などの画像は、生成時にダウンサンプリングしてから埋め込む。
解像度は、印刷用で 300dpi、閲覧用で 150dpi を目安にする。

## 電子署名と保護

| 方式                              | 法的な証拠能力         | 開発と運用の負荷         | 締結のワークフローと監査ログ |
| --------------------------------- | ---------------------- | ------------------------ | ---------------------------- |
| 電子契約サービスへ委譲            | ある                   | API 連携だけで低い       | サービスに含まれる           |
| 長期署名規格（PAdES）を自前で実装 | ある                   | 証明書の管理と実装で高い | 自前で作る                   |
| パスワード保護                    | 改ざんを検知できず低い | 低い                     | ない                         |
| 保護なし                          | ない                   | 低い                     | ない                         |

- 対外的な契約書など法的な証拠が要る帳票は、PDF の生成までをこのシステムで行い、署名と締結のワークフローを API で電子契約サービスへ委譲する。
- 本人確認、認定タイムスタンプ、長期保存、監査ログの要件を自前の実装で満たさない。
- 電子契約サービスは外部依存の追加になるため、採用するときに ADR を起こす。
- 社内向けの帳票は保護を設定しない。閲覧パスワードは RPA や OCR などの後続処理を妨げるためである。

## 長期保存規格

PDF/A（ISO 19005）は、法令や契約で求められた場合だけ採用する。
原典によれば、電子帳簿保存法は PDF/A を要件とせず、画面や書面で整然と確認できれば通常の PDF でよいとされる。
PDF/A はフォントの埋め込みが必須で、暗号化と外部ファイルへのリンクを使えないため、ファイルサイズと機能の制約を受ける。
