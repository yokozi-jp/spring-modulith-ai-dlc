# 電子帳票の形式選択

電子帳票は PDF を原則とする。
相手先に入力や加工をしてもらう必要があり、Web フォームを作れない場合だけ Excel を使う。
HTML と SVG は帳票の形式に使わない。

## 形式の比較

| 観点             | PDF                    | Excel                          | HTML                                  | SVG                              |
| ---------------- | ---------------------- | ------------------------------ | ------------------------------------- | -------------------------------- |
| レイアウトの保証 | できる                 | 一部だけできる                 | 利用者の設定に左右される              | 座標指定のためできる             |
| 改ざんの防止     | 電子署名で防げる       | 誤って変更されるおそれがある   | 開発者ツールで変更できる              | テキストのため編集できる         |
| データの二次利用 | 解析が難しい           | 容易                           | 構造によっては容易                    | 文字は持つが構造は視覚的         |
| 開発コスト       | 専用のツールが要り高い | 複雑なレイアウトでなければ低い | 簡易な帳票なら CSS Paged Media で低い | 改ページ制御を自前で作るため高い |

## 形式の選び方

- 厳密な印刷が必要な帳票と、証跡として残す帳票は PDF にし、[PDF 帳票の設計](pdf.md)に従う。
- 取引先指定の請求書の様式や、記入して返送してもらう調査票のように相手先に入力してもらう帳票は、まず Web フォームを検討する。
- Web 画面を作る時間や予算がない場合、またはオフラインで作業する必要がある場合だけ、入力用の帳票を Excel にし、[Excel 帳票の設計](excel.md)に従う。
- HTML は厳密なレイアウトの調整が難しいため、帳票の形式に使わない。
- SVG は改ページ制御を含む開発の知見が少ないため、帳票の形式に使わない。

## 生成と受け渡し

- 生成した帳票を API で受け渡す方法は、[ファイルのアップロードとダウンロード](../web-api/file-transfer.md)に従う。
- 生成に時間がかかる帳票や大量の一括生成を非同期にするかは、[非同期化の判断基準](../integration/async-adoption-criteria.md)で判断する。
