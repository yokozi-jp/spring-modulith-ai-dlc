# 可用性の定義項目チェックリスト

多くのシステムは、運用スケジュール、目標稼働率、RTO と RPO の基本項目だけで足りる。
ミッションクリティカルなシステムほど、下の表の項目まで定める。
すべての項目を埋めること自体を目的にしない。

項目の意味と決め方は[可用性要件の定め方](availability-requirements.md)に従う。

## 継続性

| 分類             | 定義項目                 | 値の例                                                               |
| ---------------- | ------------------------ | -------------------------------------------------------------------- |
| 運用スケジュール | 通常の運用時間           | 24時間365日無停止、業務時間内（9時から17時）、夜間のみ停止           |
| 運用スケジュール | 特定日の運用時間         | 祝日と年末年始も通常どおり、特定日のみ停止できる                     |
| 運用スケジュール | 計画停止の有無と許容時間 | あり（月間最大 XX 時間）、なし（無停止が必須）                       |
| 稼働率           | 目標稼働率               | 99％、99.9％、99.99％、99.999％                                      |
| 稼働率           | 計算条件                 | 計画停止を除く、大規模災害を除く、外部要因を除く、月間または年間集計 |
| 目標復旧水準     | RTO（目標復旧時間）      | 2時間以内、4時間以内、1営業日以内、数日以内                          |
| 目標復旧水準     | RPO（目標復旧時点）      | ほぼゼロ、日次（1営業日前）、週次（5営業日前）                       |
| 目標復旧水準     | RLO（目標復旧レベル）    | 全機能を復旧、主要業務のみ、縮退（参照のみ）                         |

## 耐障害性

| 定義項目                             | 値の例                                                                           |
| ------------------------------------ | -------------------------------------------------------------------------------- |
| 対象業務の範囲                       | 全業務、外部向けのオンライン処理のみ、内部の一括処理のみ                         |
| サーバーの冗長化                     | 非冗長、負荷分散、クラスタ、Active-Active、複数のアベイラビリティゾーン          |
| 電源、ディスク、ネットワークの冗長化 | RAID 相当、分散ストレージ、複数の回線事業者                                      |
| 単一障害点を排除する対象             | 重要なコンポーネントすべて、サーバーとストレージとネットワーク、外部依存を含む   |
| 同時障害への耐性                     | 単一障害でも継続、二重障害でも切り替え時間内に継続、リージョン障害は DR に委ねる |
| サービスの切り替え時間               | 60秒未満、5分以内、15分以内、60分以内                                            |
| フェイルオーバーの自動と手動         | 自動、手動（承認あり）                                                           |
| 縮退運用のレベル（RLO と対応させる） | 全機能、主要業務のみ、参照のみ                                                   |

## 災害対策と事業継続

| 定義項目                       | 値の例                                                                   |
| ------------------------------ | ------------------------------------------------------------------------ |
| DR サイトの種類                | ホットスタンバイ、ウォームスタンバイ、コールドスタンバイ、複数リージョン |
| DR の発動基準と切り替え時間    | RTO に準拠、事前に定めたきっかけ（地震の規模、データセンターの全損など） |
| 大規模災害時のシステム再開目標 | 1日以内、3日以内、1週間以内、1か月以内、再開不要                         |
| 復旧の優先順位                 | Critical、High、Medium の順序と、それぞれの復旧順                        |

## 可用性を支える運用と観測

次は運用保守性の項目だが、可用性の維持に直結するため一緒に確かめる。

| 定義項目                   | 値の例                                                  |
| -------------------------- | ------------------------------------------------------- |
| 無停止保守の要否           | 月間最大 XX 時間の停止を許す、無停止（Blue-Green など） |
| 監視と検知の時間           | 障害の検知からアラートまで5分以内、自動検知が必須       |
| 障害対応の体制             | オンコール体制、エスカレーションの初動を30分以内        |
| 可用性の確認とテストの範囲 | 業務停止となる障害の全範囲、重要業務のみ                |
| 耐障害性テストの頻度       | 四半期に1回、年2回、カオスエンジニアリングを定期に実施  |
