# フロントエンドの国際化

利用者向けの固定文言は`src/i18n/locales/`のJSON resourceに置き、react-i18nextの`useTranslation`が返す`t`で取得する。
対応言語は日本語と英語とし、既定言語は日本語にする。
ブラウザの言語設定からlocaleを解決し、文書属性、数値、複数形へ反映する。
この方式の判断理由は[ADR-016](../adr/ADR-016-localize-api-and-spa-messages.md)を参照する。

## 構成

`src/i18n/index.ts`は`createInstance`でi18nextのinstanceを作って初期化し、`i18n`としてexportする。
`main.tsx`はこのinstanceを`I18nextProvider`で渡す。
component testも同じinstanceを`I18nextProvider`で渡し、言語を切り替えるテストでは`i18n.changeLanguage`を使う。

i18nextのglobal instanceと`initReactI18next`は使わない。

resourceは同梱し、namespaceは既定の`translation`だけを使う。
namespaceの分割と遅延ロードは、文言量やbundleサイズが問題になった時点で検討する。

## locale解決

`src/i18n/resolve-locale.ts`の`resolveLocale`が`navigator.languages`の候補を優先順に評価し、結果をi18nextの`lng`へ渡す。

各候補のlanguage subtagが`ja`または`en`に一致した場合は、そのlocaleを選ぶ。

不正なlanguage tagと未対応のlanguage subtagは次の候補へ進み、対応する候補がなければ`ja`へfallbackする。

i18nextの`supportedLngs`による言語の解決と`i18next-browser-languagedetector`は使わない。

## message catalog

message catalogは`src/i18n/locales/ja.json`と`src/i18n/locales/en.json`である。

`src/i18n/i18next.d.ts`が`ja.json`から`CustomTypeOptions`の型を導くため、存在しないkeyを`t`へ渡すと型検査で失敗する。
`en.json`は`satisfies typeof ja`で検査し、不足するkeyを型検査で検出する。

message keyを追加または変更するときは、`ja.json`と`en.json`を同じ変更で更新する。

componentへ同じ表示文言を重複して埋め込まない。

interpolationの値はReactが描画時にエスケープするため、i18nextの`escapeValue`は`false`にする。
翻訳文にHTMLを含めず、文言の一部へ要素を埋め込む場合はreact-i18nextの`Trans`を使う。

## 文書属性

`i18n/index.ts`は`languageChanged`イベントで`document.documentElement.lang`を選択したlocaleへ設定する。

画面のcomponentは`t("title")`を`document.title`へ設定する。

## 数値と複数形

数値はi18nextのformatting（`{{count, number}}`）で表示し、文字列へ整形してからinterpolationへ渡さない。

複数形はi18nextのplural（`count`オプションと`_one`、`_other`などの接尾辞）で表し、componentで単数と複数を分岐しない。
日本語は`_other`だけを持ち、英語は`_one`と`_other`を持つ。

## Problem Details

APIのProblem Detailsはバックエンドが解決した利用者向け文言として扱い、フロントエンドの固定文言と混在させない。
この規則は現行Conventionであり、異なる写像方式を提案する[ADR-016](../adr/ADR-016-localize-api-and-spa-messages.md)がAcceptedになるまでは変更しない。
