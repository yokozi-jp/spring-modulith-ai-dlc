# フロントエンドの国際化

利用者向けの固定文言は、`i18n.ts`の型付きmessage catalogから取得する。
対応言語は日本語と英語とし、既定言語は日本語にする。
ブラウザの言語設定からlocaleを解決し、文書属性と数値表示へ反映する。

## locale解決

`navigator.languages`の候補を優先順に評価する。

各候補のlanguage subtagが`ja`または`en`に一致した場合は、そのlocaleを選ぶ。

不正なlanguage tagと未対応のlanguage subtagは次の候補へ進み、対応する候補がなければ`ja`へfallbackする。

## message catalog

message catalogはTypeScriptの型でmessage keyを定義し、`ja`と`en`の双方が同じ型を満たすようにする。

message keyを追加または変更するときは、`ja`と`en`の文言を同じ変更で更新する。

componentへ同じ表示文言を重複して埋め込まない。

message catalogが複数の責務へ分かれる規模になるまでは、空のlocale別ディレクトリへ分割しない。

## 文書属性と数値表示

解決したlocaleを`document.documentElement.lang`へ設定し、選択したmessage catalogのtitleを`document.title`へ設定する。

数値は選択したlocaleの`Intl.NumberFormat`を使って表示する。

## Problem Details

APIのProblem Detailsはバックエンドが解決した利用者向け文言として扱い、フロントエンドの固定文言と混在させない。
この規則は現行Conventionであり、異なる写像方式を提案する[ADR-016](../adr/ADR-016-localize-api-and-spa-messages.md)がAcceptedになるまでは変更しない。

## 日時表示

日時の解析と表示は[日時とタイムゾーンの規約](../datetime/timezone-conventions.md)に従う。
