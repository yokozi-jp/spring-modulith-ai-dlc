- [設計判断の進め方](design-decision-process.md)：複数モジュールに影響する課題や仕様変更の対応方針を決めるとき、案が決まらず手が止まったとき
- [技術選定の原則](technology-selection.md)：ライブラリ、フレームワーク、構成方式を選ぶとき、標準から外れる設計を提案するとき
- [設計の作り込みの程度と段階的な再構築](right-sizing.md)：新しい構成要素や抽象化を入れるか、将来の拡張にどこまで備えるか決めるとき
- [暫定対応と運用回避の扱い](temporary-workarounds.md)：レビューで暫定対応を求められたとき、指摘を後回しにするか判断するとき

- [設定と規約の使い分け](configuration-and-convention.md)：フレームワークの既定の動作を変えるとき、独自の命名や配置のルールを作るとき

- [Walking Skeleton による経路の先行確立](walking-skeleton.md)：新しいシステムを立ち上げるとき、外部 API やブローカーなど新しい構成要素を導入するとき
- [コーディングエージェントを前提にした標準化](ai-assisted-development.md)：モジュールやディレクトリの構成を決めるとき、標準のパターンに当てはまらない機能を実装するとき
- [名前の付いた連携パターンの利用](integration-patterns.md)：連携方式を新しく考えるとき、連携の設計文書を書くとき
- [共通基盤を作るかの判断と範囲の決め方](shared-platform.md)：共通の仕組みを作るか検討するとき、共通基盤への機能追加の要望を受けたとき
