# ストレステスト

ピーク時の負荷から段階的に負荷を上げ、性能の限界とボトルネックの構成要素を特定する。
ボトルネックを増強して性能が実際に上がることを確かめ、限界を超えたときの増強の手順を整理する。
オートスケールを構成する場合は、閾値どおりに発動し、負荷の変動を受け止められることを確かめる。

用語は[性能テストの種別と用語](terminology.md)に従う。

## 完了基準

### スケーラビリティの評価

- 負荷を上げたときにボトルネックとなる構成要素を特定した。
- ボトルネックをスケールアップまたはスケールアウトして、性能が実際に上がることを確かめた。
- オートスケールを構成する場合は、閾値どおりにスケールアウトとスケールインが発動し、負荷の変動を安定して受け止めた。

### キャパシティプランニング

- [ラッシュテスト](rush-test.md)で導いた構成の限界性能（限界のスループットなど）を特定した。
- 限界を超える負荷に対して、どの構成要素をどの順に増強するかを整理した。

## 限界性能とボトルネックの把握

1. ピーク時の負荷を起点に、段階的に負荷を上げる。
2. 各段階で、処理時間、スループット、エラー率、構成要素ごとのCPUとメモリの使用率を記録する。
3. 処理時間が目標値を超える、リソースが飽和する、エラー率が急増するなどの事象が起きた段階を限界とし、そのときに飽和している構成要素をボトルネックとする。
4. ボトルネックの構成要素だけを増強し、同じ手順で限界が上がることを確かめる。

ボトルネックではない構成要素を増強しても限界は上がらない。
限界に達した時点で余裕のある構成要素は、増強の対象から外す。

## オートスケールの確認

オートスケールは構成しただけでは期待どおりに動くとは限らないため、発動するまで負荷を上げ続けて確かめる。

- **発動の条件**：設定した閾値（例：CPU使用率70%超が2分続く）に達したときに、スケールアウトとスケールインが発動する。
  閾値、継続期間、クールダウン期間が負荷の増減の速さに合っており、スケールアウトとスケールインを繰り返さない。
- **スケールアウト**：新しいノードの起動、ヘルスチェックの完了、ロードバランサーへの組み込みまでの時間が、負荷の増加に追いつく。
  新しいノードへトラフィックが分配され、全体の性能が上がり、エラー率が閾値内に収まる。
- **スケールイン**：外されるノードが処理中のリクエストを完了してから停止する（グレースフルシャットダウン）。
  残ったノードで負荷を受け止められる。
- **範囲**：最小ノード数と最大ノード数が妥当である。
  最大ノード数に張り付いても受け止められない場合は上限の引き上げを検討し、最大に達する前に別の構成要素（DBなど）がボトルネックになる場合は上限が過剰でないかを見直す。

アプリケーションのノード数の上限は、[ADR-019](../adr/ADR-019-define-resilience-and-capacity-guardrails.md)の接続予算の不等式を満たす範囲にする。
