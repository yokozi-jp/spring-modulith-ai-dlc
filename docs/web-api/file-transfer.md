# ファイルのアップロードとダウンロード

数KB程度の小さなファイルはBase64でJSONの値に含め、それより大きなファイルはオブジェクトストレージの署名付きURLで直接送受信する。
署名付きURLは、短い有効期限とメソッド、Content-Type、サイズの制約を付けて発行する。
アップロードはメタデータの登録をもって完了とし、内容の検査を通るまでファイルを利用可能にしない。

## 前提

このリポジトリはまだオブジェクトストレージを持たない。
署名付きURLの方式を初めて実装するときは、保存先の選定をADRに記録する。
ブラウザからオブジェクトストレージへ直接接続するため、[ADR-014](../adr/ADR-014-use-same-origin-spa-security-boundary.md)のCSPの`connect-src`に接続先を追加する判断も同じ変更で行う。

## 方式の選択

- **数KB程度のファイル**（サムネイルなど）：Base64でエンコードし、JSONの項目の値に入れる。ダウンロードでは、`<img>`の`src`へそのまま設定できるデータURIの形式で返す。
- **それ以外のファイル**：オブジェクトストレージの署名付きURLを発行し、クライアントがオブジェクトストレージと直接送受信する。

## アップロードの手順

1. クライアントがAPIに署名付きURLの発行を依頼する。
2. APIが制約を付けた署名付きURLを発行して返す。
3. クライアントが署名付きURLへファイルをアップロードする。
4. クライアントがAPIにファイルのメタデータ（参照できる権限、検索用のタグなど）を登録する。

メタデータの登録をもって、アップロードの完了とする。

## 署名付きURLの制約

署名付きURLは、URLを知っていれば誰でも使えるため、次の制約を付けて発行する。

- **有効期限**：1分から5分程度に短くする。
- **HTTPメソッド**：アップロードではPOSTまたはPUTに限定する。
- **Content-Type**：拡張子とメディアタイプを検証し、許可する種類（`.png`、`.jpeg`、`.webp`など）に絞る。
- **Content-Length**：許可するサイズ（100MBまでなど）を検証してから発行する。
- **送信元**：社内ネットワークからの利用に限る場合は、保存先のアクセス制御で送信元IPを制限する。

## アップロードしたファイルの検査

拡張子とメディアタイプは偽装できるため、必要に応じてファイルの内容を検証する。
画像のEXIFは、個人情報とセキュリティの観点から削除する。
社内向けのシステムでも、リスク評価の結果に応じてマルウェアを検査する。
検査は保存先のアップロード完了イベントを契機に実行し、不合格のファイルは削除または隔離する。
